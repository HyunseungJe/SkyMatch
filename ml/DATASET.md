# 합성 하늘 데이터셋

ML 모델은 셰이더로 직접 만든 합성 이미지로 학습합니다. 이 문서는 데이터셋이 **어떻게 만들어지고 가공되는지** 전부 설명합니다.
- 숫자의 원본은 설정 파일([`datasets/v1.toml`](datasets/v1.toml))이고, 이 문서는 그 설정을 사람 말로 풀어 쓴 것입니다.
- 둘이 어긋나면 설정 파일이 맞는 것이고, 이 문서를 고쳐야 합니다.

## 한눈에 보기

```
설정(v1.toml) ──► 표본 i마다 난수 생성기 SeedSequence([seed, split_id, i])
                  ├─ 학습 대상 파라미터 θ 샘플링     (스키마 role = regress / classify)
                  ├─ 방해 파라미터 샘플링            (role = artist 중 이미지에 보이는 것)
                  ├─ 하늘색 3개 샘플링               (그럴듯한 색 70 % / 무작위 30 %)
                  └─ 카메라 샘플링                   (피치, 세로 화각)
             ──► 렌더: sky/skyV1.glsl 그대로, 웹 사진 맞추기와 같은 표시 변환 (노출 1 → AgX, 디더 없음)
             ──► 저장: 256×192 sRGB uint8 묶음(.npy) + 표본별 라벨(.jsonl) + manifest.json
             ──► (학습할 때) 증강 → 아래 「증강」 절
```

- **재현성:** 같은 설정, 같은 커밋, 같은 표본 번호면 같은 θ와 카메라가 나옵니다. 표본마다 난수 스트림이 따로라서, 순서나 병렬 처리와 상관없이 결과가 같습니다.
- **이미지 픽셀:** GPU와 드라이버가 다르면 아주 드물게 ±1~5 정도 다를 수 있습니다. 웹 렌더러와 비교한 결과, 채널 값의 99.96%가 같았습니다.

## 1. 학습 대상

학습 대상은 [스키마](../sky/sky_schema_v1.json)의 `role`이 정합니다.
- **회귀:** 해 고도, 천정색, 지평선색, 해 빛색, 안개, 구름 양, 구름 밀도, 구름 크기, 구름 부드러움, 폭풍, 별, 은하수 밝기, 오로라 세기, 오로라 색조
- **분류:** 밤 효과(없음, 은하수, 오로라)

**보이지 않는 파라미터는 손실에서 뺍니다.** 그 순간 이미지에 흔적을 남기지 않는 파라미터는 맞힐 수 없기 때문입니다. 조건은 스키마의 `mask` / `activeWhen`을 그대로 씁니다. 예를 들면 다음과 같습니다.
- 구름 양 < 0.05이면 구름 밀도, 크기, 부드러움, 폭풍은 학습하지 않습니다.
- 해 고도 ≥ −6°이면 별과 밤 효과는 학습하지 않습니다.
- 밤 효과가 오로라일 때만 오로라 세기를 학습합니다.

표본마다 이 판정 결과를 라벨의 `active`에 저장합니다.

## 2. 파라미터 분포 (v1)

| 파라미터 | 분포 | 이유 |
|---|---|---|
| 해 고도 | 45 %: 균등 [−12°, 60°], 45 %: 균등 [−12°, 15°], 10 %: 균등 [−12°, −6°] | 지평선 근처에서 모습이 가장 빨리 바뀌므로 그쪽을 더 촘촘히. 마지막 항은 밤 표본(별, 은하수, 오로라가 보이는 −6° 아래)을 약 24 %로 늘림 |
| 안개 | 50 %: 균등 [0, 0.3], 50 %: 균등 [0, 1] | 옅은 안개가 흔함 |
| 구름 양 | 20 %: 0(맑음), 80 %: 균등 [0, 1] | 완전히 맑은 하늘도 충분히 |
| 구름 밀도 | 로그 균등 [0.2, 5] | 스키마가 로그 척도 |
| 구름 크기 | 로그 균등 [0.25, 1.5] | 스키마가 로그 척도 |
| 구름 부드러움 | 균등 [0, 1] | |
| 폭풍 | 60 %: 0, 40 %: 균등 [0, 1] | |
| 별 | 균등 [0, 2] | 밤(해 고도 < −6°)에만 보임 |
| 밤 효과 | 없음 50 %, 은하수 25 %, 오로라 25 % | 밤에만 보임 |
| 은하수 밝기 / 오로라 세기 / 오로라 색조 | 균등 [0, 2] / [0, 3] / [0, 1] | 해당 효과일 때만 보임 |

결과는 스키마 범위 안으로 자릅니다.

## 3. 하늘색

하늘색 세 개(천정, 지평선, 해 빛)는 표본마다 두 방식 중 하나로 뽑습니다.

**무작위 (30 %).** 세 색을 각각 sRGB 정육면체에서 균등하게 뽑습니다. 초록 천정에 빨간 지평선처럼 실제로는 드문 하늘도 나옵니다. 셰이더의 표현 범위 전체를 학습하게 하려는 의도입니다.

**그럴듯한 색 (70 %).** OKLCh 색 공간(L 밝기, C 채도, h 색조)에서 아래 규칙으로 뽑습니다.
- **밝기:** 해 고도 단계에 따라 천정 밝기 L을 정합니다. 지평선 밝기는 천정 L에 오프셋을 더합니다.
  - 낮(≥ 0°): 천정 L [0.40, 0.85], 지평선 오프셋 [0, +0.25]
  - 박명(−6° ~ 0°): 천정 L [0.15, 0.60], 지평선 오프셋 [−0.05, +0.30]
  - 밤(< −6°): 천정 L [0.00, 0.30], 지평선 오프셋 [−0.03, +0.20]
- **천정:** 15 %는 회색(채도 [0, 0.02]), 나머지는 색조 [215°, 310°](하늘색 → 파랑 → 보라. OKLCh 190°는 이미 청록이라 뺌), 채도 [0.02, 0.18]입니다.
- **지평선:** 색조는 노랑-초록 ~ 초록 띠 [100°, 170°]를 뺀 전체 원에서 균등, 채도 [0, 0.18]입니다.
- **해 빛:** 10 %는 검정(빛 없음)입니다. 나머지는 밝기 [0.50, 0.98], 채도 [0, 0.20]이고, 색조는 80 %가 따뜻한 띠 [20°, 110°](빨강 → 노랑), 20 %가 전체 원(분홍, 보라 빛)입니다.
- **sRGB 범위 밖의 색:** 밝기와 색조는 그대로 두고 채도만 줄여서 넣습니다(이분 탐색).

어느 방식으로 뽑았는지는 라벨의 `color_mode`에 남깁니다.

## 4. 방해 파라미터와 고정값

학습 대상은 아니지만 이미지를 바꾸는 값입니다. 모델이 이 값들에 흔들리지 않도록 무작위로 바꿉니다.
- **해 방위(시선 기준):** 60 %는 [−60°, 60°](해 쪽을 보는 사진), 40 %는 전체 [−180°, 180°]입니다.
- **시간 [0, 600] s:** 구름 무늬, 오로라 흐름, 별 반짝임이 매번 달라집니다.
- **은하수:** 기울기, 방위, 폭을 각 스키마 범위에서 균등하게 뽑습니다.
- **오로라:** 방위, 퍼짐, 높이를 각 스키마 범위에서 균등하게 뽑습니다.

나머지는 스키마 기본값으로 고정합니다. 사진 맞추기와 같은 조건입니다.
- 달 없음, horizonWarmth 0, nightBrightness 1, 노출 1, 구름 속도·바람 방향, 오로라 속도

## 5. 카메라

사진처럼 보이는 원근 시점입니다.
- **방위(yaw):** 0으로 고정합니다. 해의 상대 위치는 해 방위가 정합니다.
- **피치:** 70 %는 [−5°, 20°](지평선이 보이는 사진), 30 %는 [20°, 60°](위를 올려다본 사진)입니다.
- **세로 화각:** [35°, 75°]입니다.

지평선 아래 방향에는 셰이더가 그리는 바닥색 띠가 나옵니다. 실사진에서는 이 부분이 땅이나 건물이라서, 학습할 때 증강으로 가립니다(「증강」 절).

## 6. 렌더와 저장

- **렌더러:** [`skymatch_ml/render.py`](skymatch_ml/render.py)는 `sky/skyV1.glsl`과 웹 래퍼(`web/src/sky/skyShader.ts`)를 실행할 때 읽어 씁니다. 셰이더를 복사하지 않습니다.
- **출력:** 웹 사진 맞추기 렌더러(`fitRenderer.ts`)와 같습니다. 노출 1 → AgX 근사 → 8비트, 디더 없음.
- **해상도:** 256×192입니다. 학습 입력 크기는 학습 설정에서 따로 정합니다.
- **파일 구성:**
  - `<split>/images-NNNNN.npy`: `uint8 [n, 192, 256, 3]`, 위쪽 행부터. 한 묶음에 4096장입니다.
  - `<split>/labels-NNNNN.jsonl`: 같은 순서로 한 줄씩입니다. θ(웹의 θ JSON과 같은 형식, 색은 `#rrggbb`), 카메라, `active`, `color_mode`가 들어갑니다.
- **분할:** 학습용 180,000 / 검증용 10,000 / 생성 평가용 10,000입니다. 분할마다 난수 스트림(`split_id`)이 따로라서 서로 겹치지 않습니다.
- **`manifest.json`:** 생성할 때마다 쓰고, 아래 항목이 들어갑니다.
  - 설정 파일 원문과 해시
  - Git 커밋(수정 중이던 파일이 있었는지 포함)
  - 셰이더, 스키마, 노이즈 텍스처, 래퍼의 해시
  - 실제 렌더러(GPU 이름)
  - 라이브러리 버전, 생성 수량, 소요 시간

## 7. 증강 (학습할 때 적용)

증강은 저장된 이미지에 미리 적용하지 않습니다. 학습할 때 표본별 시드로 적용해서, 재현할 수 있고 기록도 남깁니다. 단계는 학습 코드와 함께 정의하고, 그때 이 절에 다음을 적습니다.
- 각 단계의 이름, 확률, 범위
- 순서

예정된 단계는 다음과 같습니다(확정 전).
- 지평선 아래를 무작위 실루엣 모양으로 가리기
- 노출과 화이트밸런스 흔들기
- 센서 잡음
- JPEG 압축

## 8. 알려진 한계

- **무작위 색:** 실제로 드문 하늘이 많이 나오는 것은 의도한 것입니다.
- **밤 표본 비율:** v1 설정에서 해 고도 < −6°인 표본은 약 24 %이고, 은하수와 오로라 표본은 각각 그 4분의 1(전체의 약 6 %)입니다. 모델이 밤 효과를 잘 못 맞히면 이 비율을 먼저 의심해야 합니다.
- **셰이더가 표현하지 못하는 현상은 데이터에 없습니다.** 무지개, 햇무리, 빛살 등이 여기에 해당합니다.

## 실행

```sh
cd ml
uv sync
uv run python -m skymatch_ml.generate --config datasets/v1.toml --out <출력 폴더> --preview 64
# 시험: --limit 256 (분할마다 256장)
# Linux 서버(화면 없음): --backend egl
```
